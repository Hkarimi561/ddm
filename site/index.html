Docker download manager

Docker pulls that survive bad networks.

ddm downloads Docker images over parallel, resumable connections, checks every byte, and loads them into Docker under their original name. If the network drops, the laptop sleeps or you press Ctrl+C, run the command again and it continues from the exact byte where it stopped. If a mirror lets you down, it moves to the next one without losing a byte. And you can keep typing docker: ddm steps in only when a command needs something downloaded, AI models for Docker Model Runner included.

~ — bash

      

    


    

      
Built for unreliable connections

      
Docker's own puller starts layers over when the connection breaks. ddm talks to the registry itself and treats every byte it already has as kept.

      

        

          

          
Resumes to the byte

          
Progress is saved every second and on exit. Ctrl+C, a crash or a reboot all pick up where they left off.

        

        

          

          
Parallel segments

          
Each blob is fetched over several HTTP Range connections, each on its own TCP stream, with redirects to CDNs followed.

        

        

          

          
Verified, chunk by chunk

          
Every blob must match its sha256. If data rots on disk, only the damaged chunks are downloaded again.

        

        

          

          
Never gives up

          
Retries forever with backoff and jitter, and replaces stalled connections. When the network returns, the download carries on.

        

        

          

          
Atomic import

          
The finished image is streamed into docker load. Docker registers it only when everything has arrived, so it never ends up half-imported.

        

        

          

          
One static binary

          
Linux, macOS and Windows on amd64 and arm64. Docker is the only other thing it needs, and it reuses your docker login credentials.

        

      

    


    

      
Mirrors that hand over mid-download

      
Give each registry a list of mirrors. ddm tries them in order, with the registry itself last, and switches the moment one stops pulling its weight. Bytes are identified by their digest, so the next mirror picks up exactly where the last one stopped.

Make plain docker use ddm

            
One line in your shell's startup file. Skip it once with command docker, or turn it off with DDM_PASSTHROUGH=off.

            

              
bash / zsh
eval "$(ddm shell-init bash)"

              
fish
ddm shell-init fish | source

              
PowerShell ($PROFILE)
ddm shell-init powershell | Out-String | Invoke-Expression

            

          

        

      

    


    

      
AI models that arrive in one piece

      
Models for Docker Model Runner run to gigabytes, which is exactly where a flaky connection hurts. ddm model pull downloads them with the same resumable, verified engine, then loads them into Model Runner under the name docker model expects.

      

        

          

          
Docker Hub & registries

          
Models such as ai/smollm2 come down in segments, resume after any interruption, and use your mirrors. They're loaded with their original manifest, so the model ID matches a normal docker model pull.

        

        

          

          
Hugging Face (hf.co/…)

          
When Model Runner downloads from Hugging Face itself, any error starts the file over and nothing checks its contents. ddm resumes, verifies every file against the Hub's sha256, and picks the same quantization (Q4_K_M unless you name one). It also works through mirrors like hf-mirror.com.

        

        

          

          
Checks before it starts

          
Is the docker model plugin installed and the runner running? If not, ddm says how to fix it and offers to turn the runner on, after asking. It also warns when a model won't fit in memory or GPU memory.

Stay in control

      
Big downloads take a while. Check on them from another terminal, pause them when you need the bandwidth, cap their speed, start them at night, and reclaim the disk space afterwards.

      

        

          

          
Status, pause, resume

          
ddm status shows every running download with speed, ETA and the mirror each file comes from. ddm pause stops them within a second and keeps every byte; ddm resume picks up exactly there.

        

        

          

          
Speed limits & scheduling

          
Cap all downloads with --limit-rate 2MiB or a default in the config, and change it on the fly with ddm limit. --start-at 02:00 waits for off-peak hours.

        

        

          

          
A tidy cache

          
ddm cache ls lists what's cached and when it was last used. ddm cache gc deletes what nothing needs and stale partial downloads, but never touches a download in progress.

How it works

      
ddm skips Docker's downloader and only hands Docker the finished result. No network is involved in that last step.

      
    
        
  1. ResolveFetch the manifest and pick the entry for your Docker engine's platform from multi-arch images.
    2. 
        
  2. Skip what you haveImages already in Docker and blobs already in the ddm cache are not downloaded again, so shared base layers come down once.
    3. 
        
  3. Download in segmentsBlobs are split into chunks and pulled in parallel. Offsets and running hashes are written to disk continuously.
    4. 
        
  4. VerifyEach blob is checked against its sha256. Corrupt chunks are found and fetched again on their own.
    5. 
        
  5. Load into DockerThe verified image goes into docker load under its original name, as if it had been pulled normally.

Usage

      
The same command starts a download and resumes it.

      

        

          
CommandWhat it does

          
            
ddm pull nginx:latestDownload, verify and load into Docker

            
ddm pull --platform linux/arm64 IMAGEPull a specific platform from a multi-arch image

            
ddm pull -c 8 IMAGEUse 8 connections per blob (default 4)

            
ddm pull -p 5 IMAGEDownload 5 blobs at once (default 3)

            
ddm pull --no-load IMAGEOnly download into the cache, e.g. while Docker is stopped

            
ddm pull --stall-timeout 1m IMAGEReplace a connection after it has sent nothing for a minute

            
ddm pull --verbose IMAGEShow every retry and its cause

            
ddm mirror add docker.io URLAdd a mirror; --first tries it before the others

            
ddm mirror test docker.io --applyMeasure every mirror and save the fastest order

            
ddm mirror listShow mirrors in the order they are tried

            
ddm config set proxy socks5://127.0.0.1:1080Send registry traffic through a proxy (http, https or socks5)

            
ddm config listShow every setting and where the config file lives

            
ddm docker compose up -dDownload the project's missing images, then run compose

            
ddm doctorCheck Docker, the cache, the config and every registry endpoint

            
ddm shell-init bashPrint a docker function that goes through ddm

            
ddm model pull ai/smollm2Download a model and load it into Docker Model Runner

            
ddm model pull hf.co/org/repo:Q4_K_MDownload a Hugging Face GGUF model, verified file by file

            
ddm docker model run ai/gemma3Check the runner, fetch the model if missing, then run it

            
ddm mirror add hf.co https://hf-mirror.comFetch Hugging Face models through a mirror

            
ddm statusShow running downloads, speed, ETA and unfinished downloads

            
ddm pause / ddm resumePause and resume running downloads without losing data

            
ddm limit 1MiBChange the speed limit of running downloads

            
ddm pull --start-at 02:00 IMAGEStart a download at a given time

            
ddm cache gc --older-than 30dFree disk space taken by old downloads
