Docker download manager

Docker pulls that survive bad networks.

ddm downloads Docker images over parallel, resumable connections, checks every byte, and loads them into Docker under their original name. If the network drops, the laptop sleeps or you press Ctrl+C, run the command again and it continues from the exact byte where it stopped. If a mirror lets you down, it moves to the next one without losing a byte.

~ — bash

      

    


    

      
Built for unreliable connections

      
Docker's own puller starts layers over when the connection breaks. ddm talks to the registry itself and treats every byte it already has as kept.

      

        

          

          
Resumes to the byte

          
Progress is saved every second and on exit. Ctrl+C, a crash or a reboot all pick up where they left off.

        

        

          

          
Parallel segments

          
Each blob is fetched over several HTTP Range connections, each on its own TCP stream, with redirects to CDNs followed.

        

        

          

          
Verified, chunk by chunk

          
Every blob must match its sha256. If data rots on disk, only the damaged chunks are downloaded again.

        

        

          

          
Never gives up

          
Retries forever with backoff and jitter, and replaces stalled connections. When the network returns, the download carries on.

        

        

          

          
Atomic import

          
The finished image is streamed into docker load. Docker registers it only when everything has arrived, so it never ends up half-imported.

        

        

          

          
One static binary

          
Linux, macOS and Windows on amd64 and arm64. Docker is the only other thing it needs, and it reuses your docker login credentials.

        

      

    


    

      
Mirrors that hand over mid-download

      
Give each registry a list of mirrors. ddm tries them in order, with the registry itself last, and switches the moment one stops pulling its weight. Bytes are identified by their digest, so the next mirror picks up exactly where the last one stopped.

How it works

      
ddm skips Docker's downloader and only hands Docker the finished result. No network is involved in that last step.

      
    
        
  1. ResolveFetch the manifest and pick the entry for your Docker engine's platform from multi-arch images.
    2. 
        
  2. Skip what you haveImages already in Docker and blobs already in the ddm cache are not downloaded again, so shared base layers come down once.
    3. 
        
  3. Download in segmentsBlobs are split into chunks and pulled in parallel. Offsets and running hashes are written to disk continuously.
    4. 
        
  4. VerifyEach blob is checked against its sha256. Corrupt chunks are found and fetched again on their own.
    5. 
        
  5. Load into DockerThe verified image goes into docker load under its original name, as if it had been pulled normally.

Usage

      
The same command starts a download and resumes it.

      

        

          
CommandWhat it does

          
            
ddm pull nginx:latestDownload, verify and load into Docker

            
ddm pull --platform linux/arm64 IMAGEPull a specific platform from a multi-arch image

            
ddm pull -c 8 IMAGEUse 8 connections per blob (default 4)

            
ddm pull -p 5 IMAGEDownload 5 blobs at once (default 3)

            
ddm pull --no-load IMAGEOnly download into the cache, e.g. while Docker is stopped

            
ddm pull --stall-timeout 1m IMAGEReplace a connection after it has sent nothing for a minute

            
ddm pull --verbose IMAGEShow every retry and its cause

            
ddm mirror add docker.io URLAdd a mirror; --first tries it before the others

            
ddm mirror test docker.io --applyMeasure every mirror and save the fastest order

            
ddm mirror listShow mirrors in the order they are tried

            
ddm config set proxy socks5://127.0.0.1:1080Send registry traffic through a proxy (http, https or socks5)

            
ddm config listShow every setting and where the config file lives
